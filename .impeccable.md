## Design Context

### Users
Mixed audience: hiring managers evaluating technical depth, developers discovering tools (markymark, future projects), and general professional visitors looking for a home base. The site must work for all three without pandering to any — a technical person's personal site, not a resume template or a SaaS landing page.

### Brand Personality
**Bold, opinionated, technical.**

This is someone who builds serious developer tools in Rust, cares about LSP and MCP protocols, and ships real infrastructure. The site should feel like the person behind it has strong engineering taste — not flashy, not safe, not generic. Confidence without arrogance. Technical depth without gatekeeping.

### Aesthetic Direction
- **Visual tone:** High contrast, decisive typography, structured layouts with intentional asymmetry. Think editorial design meets technical documentation — not startup landing page, not portfolio template.
- **Anti-references:** Default Tailwind blue/gray, centered-everything layouts, glassmorphism, gradient text, card grids with icons, "Welcome to my corner of the internet" energy. Nothing that looks AI-generated or template-derived.
- **Theme:** Both light and dark via `prefers-color-scheme`. Neither mode is an afterthought — both should feel intentional.
- **Color direction:** NOT default blue. A distinctive accent that feels technical and opinionated — could be a warm amber/ochre, a sharp teal, a deep indigo, or something unexpected. Neutrals should be tinted (warm or cool), never pure gray/black/white.
- **Typography:** Distinctive, not generic. A display face with character for headings, a clean readable face for body. Variable weight preferred. No system defaults, no Inter/Roboto/Open Sans.

### Design Principles
1. **Substance over decoration.** Every element earns its place. No ornament without function.
2. **Technical credibility.** The design should feel like it was built by someone who understands systems — precise, considered, no hand-waving.
3. **Opinionated defaults.** Make bold choices and commit. A decisive wrong choice is better than a safe non-choice.
4. **Respect the reader.** Fast load, clear hierarchy, accessible by default. Don't waste people's time with animation or complexity that doesn't serve comprehension.
5. **Dark and light are peers.** Neither theme is a degraded version of the other.
